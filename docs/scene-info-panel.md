# Scene Info Panel

**Read this when:** touching the scene info panel (`src/components/slide/SceneInfo/`), adding a field it can show, or changing how it's customised.

---

## Overview

The panel across the bottom of a slide showing the scene's details. It's opened with the `show-scene-info` action button or the `i` key (`globalState.sceneInfoOpen`, shared by every slide). On marker slides it shows the marker's scene.

Which fields it shows, on which lines, and which of them are right-aligned, is up to the user and persists in `tvConfig.sceneInfoLayout` (Stash plugin config, so it syncs across devices).

## Structure

| Path | Purpose |
|---|---|
| `index.tsx` | The panel: its edit button, and its fields laid out on their lines (each line a `.field-line` flexbox with its left fields and its right-aligned ones side by side, each in a `.line-fields` box wrapping on its own, at least 2em apart, the right-aligned box pushed to the right by `margin-left: auto` and laid out from the line's end: `row-reverse`, so the first right-aligned field is at the end and rows wrap starting there, mirroring the left fields) |
| `fields.tsx` | One component per field, rendering the field's value (as its options say) or `null` when the scene has none. `SceneInfoField` renders a field by id |
| `SceneInfoEditor.tsx` | The edit mode: pills, dragging, the unused fields and the name / value switch |
| `SceneInfoFieldOptionsModal.tsx` | A field's options dialog, opened from its pill, with the controls for each field's options |
| `scene-info-config.ts` | Field ids and names, the layout type and default, the fields' options and their defaults (`resolveFieldOptions`), and the pure functions behind editing (`placeField`, `getDropTarget`, `sideAt`, `fieldsNotInLayout`) |

## Fields

Studio (with its parent studios), title (linking to the scene in Stash, and pausing the video when clicked), performers, date, details, tags, groups, studio code, director, rating, duration, resolution, frame rate, play count, o-count, file path and URLs, and spacers (see "Spacers"). Some can be shown more than one way (see "Field options"). Fields are their own size (the panel's text size): there's no smaller size set for them.

- A field renders nothing when the scene has no value for it, so its line takes no space (or is shorter). The exceptions are the rating and o-count shown as controls, which show without a value too, so one can be given.
- The date is formatted as on the scene's page in Stash (`FormattedDate` with the `long` format, e.g. "14 February 2025"), and the frame rate with Stash's own message ("24 fps").
- The rating, as a control (the default), is Stash's `RatingSystem` via its stash-ui wrapper (stars or a number, following the rating system set in Stash), which sets the rating. As with the rate scene action button, hovering the current rating's star shows "Clear" where the rating's shown, and with no rating the stars show (none, or one too small for a star), nothing's shown beside them (not even the rating a hovered star would give). That's on the side away from the fields beside it (`valueSide`: after the stars in a left field, before them in a right-aligned one), so the stars don't move as it comes and goes. As text it's out of 5 or 10.
- The o-count, as a control (the default), is a button with the o-counter icon and the count, which behaves as the o-counter action button does: its icon is an outline until the scene's been marked since the slide was shown, a click marks it (and turns the icon solid), and once marked a click opens the o-counter's −/+ controls above it. Both share `useOCounter` and `OCounterControls`, and the slide's `preIncrementOCounterValue`, so they agree on whether the scene's been marked.
- The resolution shows its name (`TextUtils.resolution`, e.g. "1080p") or its dimensions ("1920×1080").
- The play count and the o-count shown as text are labelled with an icon (the default: an eye and the o-counter's splash) or their name. The performers are labelled with a person icon (the default) or their name, or not labelled, and the resolution isn't labelled (the default) or is labelled with an icon (`assets/resolution.svg`) or its name (`labelProps`, `sceneInfoFieldLabelIcons`). The icon has the field's name for screen readers and as its tooltip. The play count's and o-count's icons are outlines while their count is 0 and solid once it isn't. With their icon they're shown at 0 too (the outline says so), and with their name only once they're more than 0.
- The details are cut short after 3 lines (`-webkit-line-clamp`) unless always shown in full. Only when they don't all fit are they clickable, to show the rest and to cut them short again. Each slide has its own.
- The tags are cut short after 2 rows unless all always shown, every row shown in full: the rows are measured from where the tags are laid out (`offsetTop`, with a `ResizeObserver`), and the list's `max-height` ends at the second row's bottom. A "Show N more" link below them (in the text's colour) (at the end they're aligned to), counting the tags hidden, shows every tag, which then stay shown for that slide. They're only cut short if at least 2 tags would be hidden (`minHiddenTags`): the button would take about as much room as one tag. ⚠️ An earlier version showed a third row faded out under "Show more", which took the room of a row without being readable.
- In the editor's pills, the values aren't interactive (`preview`): the rating's control is disabled, and the o-count's button, the details and "Show more" aren't clickable.
- Values that don't explain themselves (a number, a code) show the field's name first (`Field`'s `showLabel`) or an icon standing in for it (`Field`'s `icon`).
- A line's fields, and the line's two sides, are centred vertically on it (`align-items: center`), so values of different heights (a title, stars, icons) line up.
- What's in a right-aligned field is right-aligned too (`text-align: right`, and the end of the row for the fields that are flexboxes, like tags), in the panel and in the editor's pills showing values.
- Tags are spaced by their list's `gap` alone: Stash's margin around each `.tag-item` is removed. They're outlined in the text's colour, on no background, rather than Stash's filled badges.
- Fields render only while they're in the layout, so a hidden field's work (e.g. fetching the studio's parent studios) doesn't happen.

To add a field: add its id to `sceneInfoFieldIds` and its name to `sceneInfoFieldLabels` (`scene-info-config.ts`), and its component to `sceneInfoFieldComponents` (`fields.tsx`). It starts out of the default layout, among the unused fields.

## Field options

Fields that can be shown more than one way have an options button (FontAwesome's pen-to-square, a little bigger than the ×) on their pills on the lines (`.field-options`, beside the ×), which opens their options dialog (`SceneInfoFieldOptionsModal`, built on `ConfigItemModal`). The unused fields' pills don't have one: they're buttons themselves.

| Field | Options (default first) |
|---|---|
| Rating | Shown as a rating control or as text |
| O-count | Shown as a button, like the o-counter action button, or as text |
| Details | Cut short after 3 lines, or always shown in full |
| Tags | Cut short after 2 rows, or all always shown |
| Performers | Labelled with an icon or their name, or not labelled |
| Play count | Labelled with an icon or its name |
| O-count, as text | Labelled with an icon or its name (offered only while it's shown as text) |
| Resolution | Its name or its dimensions; not labelled, or labelled with an icon or its name |
| Spacer (each its own) | Small, medium or big |

- Options are part of the editor's draft, like the layout: the dialog's **Save** puts them in the draft, and the editor's **Save** stores them (**Cancel** discards them). **Reset to default** resets them too, and it's offered whenever the layout or the options aren't the defaults.
- Pills showing values show them as the options in the draft say.
- A choice is a button group, as in the editor's "Show…" buttons. A choice can be something other than text (`ChoiceLabel`'s `content`): an icon (e.g. a label's "Icon", sized to the text, as some icons fill whatever they're in), or "None" in italics, as it isn't literally the label, as the others are. Those are named for screen readers and in their tooltip. An option can be hidden while the field's other options make it irrelevant (`shown`).
- Values in pills look as in the panel: Stash's `.tag-item .btn` rule (faded, padded) is undone for the rating's buttons, as it greyed the stars and moved the outlines away from the filled stars over them.
- The options button works like the ×: pressing it and dragging still drags the pill, a drag's closing click doesn't open the dialog, and the ghost and the dragged pill have one too, so they're the same size. A field dragged in from the unused fields is measured with both (`copyOfDraggedPill`).
- To add an option: add it and its default to `SceneInfoFieldOptions` and `defaultSceneInfoFieldOptions`, its allowed values to `sceneInfoFieldOptionChoices` if it's a choice between strings (`resolveFieldOptions` checks values against these), and its control to `optionControls` (`SceneInfoFieldOptionsModal.tsx`). A field's first option also gives it the options button.

## Spacers

A spacer is space between fields: beside them on a line, or, when no other field on its line shows anything, above and below it (`.field-line:not(:has(.field:not(.field-spacer)))`). Its size (small, medium or big: 0.5, 1.5 or 3em beside fields, and 0.5, 1 or 2em between lines) is an option of its own.

- A line's fields have no gap between them (`.line-fields`): the space between them is up to spacers. A gap would come either side of a spacer too, so even the smallest spacer doubled the space between two fields. A line's two sides are still kept apart (`--line-sides-gap`).

- It's a repeatable field (`isRepeatableField`): it's always among the unused fields, and adding it (dragging it up or tapping it) adds a new instance of it (`newFieldInstance`), leaving it there. Dragged up, the instance is made as the drag starts, so its ghost and its pill once it's dropped are the same element (the same key).
- Each instance is an object in the layout, `{ field, id, options }`, with its options its own (`resolveFieldOptions(config, entry)`), not in `sceneInfoFieldOptions`, so they go with it when it's removed. The `id` tells it apart from others that are just the same, to keep track of it as it moves. Code goes through `entryField`, `entryKey` (its key and its pill's `data-key`) and `entryLabel` rather than treating entries as strings. Its options dialog sets its options in the layout (`replaceEntry`). New repeatable fields need only be added to `repeatableFields`.
- An instance's pill is named after its size ("Big spacer"), the one among the unused fields "Spacer", even showing values. Showing values, an instance's pill shows its name, there being nothing else to see.
- In the editor a spacer isn't drawn as a pill (`.spacer-pill`): just its name and its buttons, in muted text, with no badge, outline or padding, as it's space rather than a field. Its name never wraps, even showing values, where other pills' text wraps as a line's sides shrink to fit. ⚠️ Making the line's sides stretch (`flex: 1`) to stop it wrapping took away the space after a line's fields, which is how fields are dragged to be right-aligned (see `sideAt`).
- Not editing, spacers on lines of their own with nothing shown between them (the lines between have no values for the scene) collapse to the biggest of them (the first, of the same size): the others' lines get `.collapsed-spacer`. Otherwise they'd add up to more space than any of them. With nothing shown before them, or after them (e.g. on lines between the panel's top and fields with no values for the scene), they'd be space at the top or bottom of the panel, so they all collapse. It's worked out from what's rendered (`collapseSpacers`, after every render of the panel's lines), as whether a field shows anything is up to the field.

## Customising the panel

The pencil button in the panel's top right corner switches the panel to edit mode. Changes are made to a draft (`globalState.sceneInfoDraft`, the layout and the fields' options): **Save** stores it, and **Cancel**, or closing the panel, discards it. The draft is global, not the slide's, so editing carries on with the same changes if the feed moves to another video (e.g. when one ends), as does whether the pills show names or values (`globalState.sceneInfoEditorPillContent`). Every rendered slide's panel shows the editor, so the next slide's is already the editor as it scrolls into view; showing it only on the current slide had the panel turn into the editor once it arrived.

- Each field becomes a pill, on the same lines as in the panel. A pill's × removes the field. Pills are Stash's tag badges (`Badge variant="secondary"` with `.tag-item`, see AGENTS.md § "File Structure Best Practices"), so their CSS only lays them out and handles dragging. The space between a field and its × is the pill's flex `gap` (Stash's margin and padding on `.tag-item .btn` are zeroed), so pills without a × have even padding too. The × is drawn larger and less faded than Stash's, and its `::after` extends its hit area for touch without taking up more room.
- The fields not in the panel are always listed below the pills, or beside them on a screen wider than it's tall (`.side-by-side`, from `useWindowSize`, which allows for forced landscape). Dragging one up puts it where it's dropped, and tapping one adds it on a new line at the bottom. Dragging a pill down onto that list removes it. They're listed in their usual order, and a field dragged onto them shows its ghost in its place in that order.
- The **Show… Field name / Field value** button group (styled like the Add Channel dialog's) switches the pills between the fields' names and their values for this scene. Showing values, each pill shows its field as the panel does (the title's size, the studio chain, tag badges…), outlined instead of filled (`.editor.showing-values`). Values aren't clickable in pills. Their outline is fainter than the names' badges. A field with no value for the scene shows "No <field>" in sentence case (`noValueLabel`: a first word that's simply capitalised is lowercased, so "No studio code" but "No URLs"), faded and in italics (from CSS, via `data-empty-label`).
- **Reset to default** puts the default layout (`defaultSceneInfoLayout`: the studio, the title, the date with the resolution and frame rate right-aligned, the rating with the o-count and play count right-aligned, the performers, the tags and the details, with spacers between) in the draft. As with the settings' reset buttons, it's an `outline-warning` button shown only when the layout isn't the default.
- The buttons follow the settings panel's: full-size, with Save in its primary style (like Show Guide).

⚠️ The action button stack overlaps the panel's right side (left side in the left-handed UI), and its scrolling area is wider than its buttons. The panel reserves `--padding-right` (6.25em) beside it for its content and edit button; less than that and the stack's empty area takes the edit button's clicks. `test/e2e/scene-info-panel.test.ts` checks the button isn't covered.

⚠️ The panel scrolls when it's taller than the space above the controls, with `overscroll-behavior: contain`: the feed scrolls the page, so scrolling past the end would otherwise move on to another video.

## Moving fields

Dragging is done with pointer events in `SceneInfoEditor` (framer-motion's `Reorder`, used by the settings lists, only reorders in one direction).

**Design goal: no layout shift while dragging.** Nothing the drag shows may move the lines vertically. The field's ghost is shown in its new place only where that leaves every line exactly as tall as it is (moving pills along their line is fine). Where the ghost would change a line's height (making it wrap onto another row, a pill on it wrapping its text, or the line getting shorter), an insertion line marks the spot instead. A new line gets a ghost line between the lines, not a line of its own. The lines only move once the field's dropped. A layout shift doesn't just look jumpy: it moves what's under a pointer that's held still, so the target changes, the ghost moves, the layout changes back, and the ghost flips back and forth (thrashing). The rules below all follow from this goal. ⚠️ A change that lets the lines move mid-drag, in either mode (field names or values), breaks it. `test/e2e/scene-info-panel.test.ts` checks it with values shown, where long pills wrap their text.

- Pressing anywhere on a pill, its × included, starts a drag once the pointer moves 5px. A tap (on the pill, or on its × to remove it) isn't a drag.
- While dragging, the dragged pill follows the pointer (`.drag-overlay`), lifted and tilted so that over its ghost, which it then hides, it doesn't look like the ghost has turned solid, and the layout is shown as it will be when it's dropped, with a faded ghost of the field in its new place (`placeField` with a stand-in field). The ghost is the field's own pill (same React key), moved and dimmed, not a separate element. It keeps its × (not focusable), so it's the same size as the pill: a pill changing size as it slid looked squashed.
- Each line is a box (`.editor-line`, with `data-line`, as are its pills) holding its left pills and its right-aligned ones side by side, each in a box wrapping on its own (`.line-side.left` and `.line-side.right`), so the right-aligned pills wrap onto rows of their own, on the right, rather than onto the left fields' rows. As in the panel, the right-aligned side is laid out from the line's end (`row-reverse`), the first pill at the end. The sides are at least 2em apart (`--line-sides-gap`, the line's `column-gap`, as in the panel), so they don't run together. As a flexbox does, each side is as wide as its pills on one row while both fit, and otherwise both shrink in proportion to that width, no narrower than their widest pill. Each side's rows line up with the other's (`align-items: flex-start`). A pill (or the ghost) moving to another line or side is re-mounted there, and slides there as it keeps its `layoutId`. The space between lines is the lines' vertical margins (room for the ghost line). ⚠️ Nothing between a pill and `.editor-lines` may be positioned: pills are measured by their `offsetLeft`/`offsetTop`, relative to it (see "Where along the line").
- **Going on a line it would change the height of:** if showing the ghost on a line would make it taller or shorter than it is in the layout, the line stays as it is, with an insertion line (`.insertion-line`) where the field will go instead of its ghost. Only once the field's dropped does the line change. Whether it would is measured, not worked out (`probeLineHeight`): a hidden copy of the line (`.height-probe`) is laid out in the lines' container, with a copy of the dragged pill (with its ×) in its place, and its height compared with the copy's without it (or, on the line the field was dragged off, with it where it was). That line can't get shorter while the field's dragged (see below), so on it only getting taller counts. Heights are cached for the drag, by line, side, position and the container's width. ⚠️ An earlier version worked it out from the pills' widths (simulating each side wrapping), treating each pill as a fixed size. That held for names, but showing values, long pills (the URLs, the file path, the details) shrink and wrap their text, so the line grew without taking another row, and the sides sharing the line in proportion to their widths could make it shorter. The ghost was shown, moved the lines after it, and thrashed. Nothing moves aside for the insertion line, so where it goes along the side of the line it's over is simply by which half of a pill the pointer's over (`getSlotByMidpoints`).
- **Going on a new line:** the lines stay as they are while the field's dragged there, with a ghost line (`.ghost-line`) halfway between the lines where the new line will go, and the field's ghost leaves the line it was on. Only once it's dropped there do the lines move to make room, sliding apart. Making the new line as the field was dragged (an earlier version did) moved every line after it, and back as the field moved on. The space between lines (the lines' vertical margins) leaves room for the ghost line, and a field dragged above or below all the lines goes on a new first or last line.
- Pills slide to their new places rather than jumping, whenever the layout changes in the editor: while dragging, on the drop, and when a field is added by tapping it or removed with its ×. They're framer-motion elements with `layout="position"` (as are the toolbar and the unused fields, which move as the panel grows or shrinks) (position only, as animating size stretches their text), and a `layoutId` so they also slide between lines, between a line's sides and between the lines and the unused fields, where they're re-mounted. ⚠️ The layoutIds are scoped to each editor (a `LayoutGroup` with an id per editor): every slide has its own editor, so moving to another slide while editing had the new editor's pills slide in from where the old one's had been.
- ⚠️ framer-motion only sets an element up for layout animations if it has `layout` or `layoutId` when it mounts. Turning them on later (e.g. only during a drag) leaves the pills that were already there jumping to their new places.
- ⚠️ The ghost is dimmed with `filter: opacity()`, not `opacity`: framer-motion sets `opacity` inline on elements it lays out, which made the ghost flicker solid. Sharing a `layoutId` between a separate ghost and the field's pill had the same effect, as framer-motion cross-fades the two (not something its version here can turn off).
- ⚠️ The drop (the new layout, ending the drag, letting go of the panel) is applied in one render (`unstable_batchedUpdates`, as it happens in a window listener React 17 doesn't batch). One render at a time, the new layout was briefly shown with the old drag's ghost and target. Pills have a `layoutId`, so one moving to another line (a different parent) slides there too.
- ⚠️ The ghost has no `layoutId`, and mustn't share the dragged field's: framer-motion cross-fades elements that share one, so the ghost flickered between dim and solid as it moved. `test/e2e/scene-info-panel.test.ts` samples its opacity every frame of a drag.
- The line a field is dragged off is no shorter than it was when the drag started until the field's dropped (`min-height`, from its height then), even once it's empty (`placeField`'s `keepEmptyLines`), so the lines after it don't move up and back. Without it, a field leaving a line that wrapped (or that it made a pill wrap its text on) shrank the line.
- Targets are positions in the layout without the dragged field, with the line it was on kept even if that leaves it empty.
- **Right-aligning:** a line has fields on its left and, optionally, right-aligned fields, each side in its own box (see above). The right-aligned side runs from right to left, so its pills, the pointer, the ghost and the pointer's sideways direction are mirrored (`mirror`, x → −x) for the rules below, which then work on it as on the left side. A new row is spotted by a pill starting left of (after mirroring) *or below* the one before it (`startsRow`).
  - Which part of the line the pointer's over goes by the sides' boxes (`sideAt`). Over the empty space between them (or between one and the line's end, if the line has none of the other, or the whole line if it's empty, like the one a field was dragged off), the field goes after the left pills over the space's left two thirds, and right-aligned, after the others, over its right third: they run from the line's end, so either way it's beside the space. The boxes include the ghost, which only ever makes the space smaller on its own side, so the ghost moving to one end doesn't move the pointer onto the other's part of the space.
  - Over either side, where along it goes by that side's pills alone (the rules below), as each side wraps on its own. Arriving on the side the ghost isn't on works like arriving on the line.
  - Between lines, the ghost line covers the half of the lines (left or right) the pointer's over, and the new line's field is right-aligned if it's the right half.
  - The line a field's dragged onto has a faint highlight (`.editor-line.target`), as does the line the pointer's over while not dragging (`:hover`, only where the device can hover, or it stuck after a tap), so it's clear which right-aligned pills share a line with which left ones. It's the line's background with a `box-shadow` spread reaching 0.25em beyond its pills, with 1em corners like the pills'. A pseudo-element would need the line positioned, which would change the pills' `offsetParent` (see above).
- **Which line:** `getDropTarget` decides from the lines' positions: over a line, the field goes on that line. Between lines (or within 2px of a line's top or bottom edge), or above or below them all, it goes on a new line there. The edges are kept to a sliver so that a line is a bigger target than the gap beside it: with a quarter of each line's height as edges, a new line's target was about twice the size of a line's. A new line straight above or below the line a field was alone on would be where it already was, so it goes back on that line instead (`preferVacatedLine`).
- **Where along the line:** arriving on a line (`getSlotOnArrival`), the field takes the place of the pill it's over, whichever part of it the pointer's over, or goes after the pills to its left when it's over a gap or past the end. Taking that pill's place pushes it along, often under the pointer, so that pill (`arrivedOver`) doesn't count for the next rule for as long as the pointer stays over it. Leaving it across its far side puts the field after it. Leaving it any other way ends this: e.g. if it was pushed out from under the pointer (now over the ghost), coming back onto it swaps the two straight away. Once its ghost is on that line, `getSlotNearGhost` moves it past a pill as soon as the pointer is over that pill heading away from the ghost, so a short field passes a long one without having to reach its middle. It then stays put while the pointer carries on the same way over that pill (which is now on the ghost's other side), and only moves back once the pointer turns back. Positions along the line are where the pills are now, since they move aside for the ghost: where they're laid out (`offsetLeft`/`offsetTop`), not where they appear while sliding there. ⚠️ Measured mid-slide (`getBoundingClientRect`, which includes framer-motion's transform), pills moved under a still pointer, so the target jumped about.
- A line too long for the panel wraps onto more rows. In the editor (not the panel itself), each side's later rows are indented (a hanging indent), the left side's on the left and the right-aligned side's on the right: `--wrapped-line-indent` padding on that side of the side's box, and the same negative margin on its first pill, which always starts its first row (on the right as well, as it runs from the line's end). ⚠️ That pill's `max-width` is 100% of the box plus the indent: the box's content area is narrower than the pill by the indent, so a pill alone on its line was cut short. In the editor, a marker (`.wrapped-line-marker`) in each side's indent, centred across that side's later rows, shows they're one line: ↳ on the left, and its mirror image ↲ on the right; where the rows are is down to layout, so the editor measures them after every render and when it's resized. It's keyed by its line and side and slides with the rows (`layout="position"`) when they move. Positions along each side go by the side's row the pointer's on (`rowAt`, which spots a wrap with `startsRow`). Its rows work like lines of their own: over a pill on a different row from the ghost, the field goes after it if it's later in the line and before it if it's earlier, whichever way the pointer's moving sideways. Going after a later pill rather than taking its place puts the field roughly where that pill was, as taking the field out from before it shifts it back. Over the ghost, or on a row the ghost has to itself, nothing moves. ⚠️ Moving the ghost can move other pills between rows (e.g. the ghost going after the only pill on a wrapped row lets that pill fit back on the row above), and taking the pointer to be on the next nearest row moved the ghost back, over and over. ⚠️ Going by the whole line instead, a pointer to the right of the last pill on the *line* sent the field to the line's end, though the pointer was over the first row.
- ⚠️ Which line is worked out from where the lines were when the drag started, not where they are now. The ghost joining or leaving a line can make it wrap onto another row (or stop), moving the lines after it, so measuring them live could move the target under a pointer that was held still, and flip it back and forth.
- The toolbar, the lines and the unused fields are spaced by the editor's gap (`--editor-gap`; a flexbox, or a grid with the unused fields beside the lines), so the spacing's the same either way.
- The panel is anchored at the bottom of the slide and grows upwards, scrolling once it reaches the top of the screen. While editing, its content only clips what's outside it (`overflow: auto`) while it's actually taller than the panel can be (`.scrollable`, measured with a `ResizeObserver`): otherwise, as the panel shrank, the toolbar sliding down from where it had been was clipped until it arrived. Not editing, nothing slides, so it can always scroll, and every slide's panel doesn't have to measure itself. Its content (`.panel-content`) is a framer-motion element with `layoutScroll`, so pills sliding about allow for it being scrolled. ⚠️ The panel's max height stays on the panel itself, not the content: it has a percentage in it, which only applies to an element whose containing block has a set height (the slide, for the panel), so on the content it was ignored.
- The panel's background is an element of its own (`.panel-background`), which framer-motion animates (`layout`) to the panel's new size, so it grows and shrinks in step with the editor's contents sliding rather than snapping to its new size. Stretching a background distorts nothing, unlike animating the panel itself, whose contents would be stretched too. ⚠️ The background and content are motion elements only while editing: framer-motion measures a motion element's layout every time it renders, and with every slide's panel paying for it, the extra work was enough to make timing-sensitive tests (the keyboard rating ones) fail.
- The panel always grows upwards, dragging included: nothing moves down. While a field is dragged, neither the lines nor the unused fields shrink below their height when it started (`startingHeights`): the field leaving the unused fields, or making a line stop wrapping, would shrink the panel and move everything above. They can grow (e.g. the unused fields taking the field's ghost), which moves the lines up, so which line the pointer's over is worked out from where the lines were relative to where their container is now.
- ⚠️ An earlier version held the panel by its top while dragging, so that a line wrapping as the ghost joined it didn't move everything above (which left the pointer over another row, and the ghost moving there undid the wrap, over and over). That's now handled by not showing the ghost on a line whose height it would change (see the design goal at the top of "Moving fields"), and holding it made the panel grow downwards.
- Pointer events are followed on the window rather than on the pressed pill, which unmounts once the drag starts (it's re-rendered as the ghost).
- `placeField` removes lines left empty.
- Pills have `touch-action: none`, so dragging one on a touchscreen doesn't scroll the page (the feed). Scroll the editor by touching the space around the pills.
- ⚠️ A drag can end with a `click` on what was pressed (e.g. an unused field, whose click adds it, or a ×). `justDraggedRef` stops that click counting.
- Moving fields has no keyboard alternative yet; adding and removing them does (they're buttons).

## Config shape & persistence

```ts
// tvConfig.sceneInfoLayout — lines top to bottom, each listing its fields left to right, or, when some of them are
// right-aligned, its left fields and its right-aligned ones (each left to right)
[["studio"], { left: ["title"], right: ["rating"] }, ["performers", "date"], [{ field: "spacer", id: "…", options: { size: "big" } }]]
```

- A line is stored as a plain list unless it has right-aligned fields (`placeField` stores it that way whenever it changes), so layouts without any read the same as before right-aligning existed. Code reads a line through `lineSides` / `lineFields` rather than assuming either form.
- Positions on a line (`LayoutPosition`, `DropTarget`'s `index`) count every field on it, left then right-aligned. Between the two sides, a target's `right` decides which side it's at the end of.

```ts
// tvConfig.sceneInfoFieldOptions — the options that have been set, by field
{ rating: { display: "text" }, resolution: { format: "dimensions", label: "text" } }
```

- Stored loosely (`SceneInfoFieldOptionsConfig`), as it may have been saved by another version of Stash TV, and read through `resolveFieldOptions`: options not set get their defaults, a value an option can't take (e.g. a choice since removed) is replaced by its default, and options or fields this version doesn't know are ignored. In Stash's plugin config, like the layout.

- A field a version of Stash TV doesn't know (e.g. saved by a newer one using the same Stash server) stays where it is in the layout, but isn't shown. In the editor it's an "Unknown field" pill that can be moved or removed.
- No migration: users without the key get the default. The default's spacers have fixed ids (`default-1`…), unique only within the layout, which is all an instance's id needs.
- ⚠️ Tests that edit the layout set up a simple one of their own (`SIMPLE_LAYOUT`, in the integration and e2e panel tests) rather than relying on the default, which is long and changes.
